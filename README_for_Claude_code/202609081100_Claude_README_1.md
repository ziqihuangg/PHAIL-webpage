## 0. 一句话说清楚这是什么

这是一个**非商业、个人/研究性质**的项目页面，主题是"我们到底该怎么评测 Physical AI（机器人、具身智能、以及任何和真实物理世界打交道的模型）"。风格上不要做成产品官网/创业公司落地页，而要做成**学者的个人项目主页**那种感觉——像 [Jiajun Wu 的个人主页](https://jiajunwu.com) 那样：内容驱动、极简、没有营销感。

**名字暂定为 "PhAIL Notes"（占位，还没最终定）**——注意：`phail.ai` 这个名字已经被另一家公司 Positronic Robotics 的真机评测联盟项目占用了（他们做的是用工业级指标测机器人真机表现的排行榜），所以我们最终不会直接叫 "PhAIL"，这里只是先用一个占位名字方便开发，**请把项目名做成一个单独的变量/配置项（比如 `siteConfig.js` 里的一个字段，或者模板里的一个 `{{SITE_NAME}}` 占位符），不要在很多个文件里硬编码这个名字**，方便之后改名字的时候一次改完。

## 1. 这个项目的立场（写文案时的心态）

写这个页面的所有文案时，把自己想象成一个在做研究、诚实记笔记的人，而不是在"卖"一个产品。具体来说：

- **不要用营销语言**：不要出现"革命性""颠覆""唯一""最全面""立即体验""加入我们"这类词。
- **不需要 CTA 按钮、不需要"免费试用"、不需要 logo 墙、不需要 pricing、不需要 testimonial**。
- **可以、也应该大量引用/链接别人的工作**——这是学术页面的常态（"我们是在已有工作的基础上做整理和分析"），不是竞品分析。
- **承认自己不完整、不确定的地方**，比如"这块我们还没有一个可信的答案""这个基准我们持保留态度，理由是……"——这种坦率本身就是这个项目想传达的态度（对应 Artificial Analysis 强调"独立"、这个项目想强调"诚实"）。
- 参考语气例子（可以直接借鉴这种口吻）：

  > Artificial Analysis has spent the last two years building an independent, quantitative answer to "which AI model is actually good?" — for language, image, video, and speech models. Physical AI (models that perceive, predict, or act in the physical world) doesn't have an equivalent yet, and for good reasons: you can't call a robot the way you call an API. This is an attempt to build a small, honest piece of that missing picture — starting with a map of what's already being measured, by whom, and how well.

## 2. 设计参考：像 jiajunwu.com 那样

已经具体分析过 [jiajunwu.com](https://jiajunwu.com) 的视觉规范，直接照这个做：

- **单栏布局，左对齐，没有网格/卡片**，从上到下线性排布，段落之间靠大量留白分隔，不用分割线、不用卡片阴影、不用圆角色块。
- **配色**：白底黑字（正文黑色或深灰 `#111`），强调色是深藏青蓝 `#003366` 左右（用在链接颜色上），除此之外几乎不用别的颜色，**不要渐变、不要亮色/糖果色、不要暗色模式炫技**。
- **字体**：无衬线字体，系统字体栈即可（`-apple-system, "Segoe UI", Helvetica, Arial, sans-serif`），标题加粗加大，正文常规粗细，不用装饰性字体。
- **导航**：如果需要导航，就用页面顶部的**纯文字锚点链接**（比如 `Notes` `Landscape` `Models` `About`），不需要汉堡菜单、不需要 sticky header、不需要图标。
- **图片极少**：最多一张头像/项目相关的小图（~150-200px 宽），不需要 hero 大图、不需要插画、不需要 stock photo。
- **正文用文字和列表承载信息，不用信息卡片/图标网格**——比如"相关基准"这种内容，就是一个逐条列出、每条一两句话+链接的列表，不是一堆彩色卡片。
- **响应式**：单栏内容最大宽度控制在 700-800px 左右并居中，移动端表现自然会不错，不需要额外做复杂的移动端布局。

### 3.2 About / 项目说明（对应 Jiajun Wu 页面的开场自我介绍段落）

```
This is a research notebook, not a company.

Artificial Analysis has spent the last two years building an
independent, quantitative answer to "which AI model is actually
good?" — for language, image, video, and speech models. Physical
AI — models that perceive, predict, or act in the physical world,
from tabletop manipulation to full-body humanoid control to
autonomous driving — doesn't have an equivalent yet, and not by
accident: you can't call a robot the way you call an API.

This project is an attempt to build a small, honest piece of that
missing picture: a map of what's already being measured, by whom,
and how well; a growing, transparently-sourced comparison of the
models and benchmarks that matter; and, where something is clearly
missing, some proposals of our own.

Run out of [NTU / MMLab], updated irregularly, always a work in
progress. If you think something here is wrong, incomplete, or
missing, I'd genuinely like to hear about it — see Contact below.
```

### 3.3 Scope / "What we mean by physical AI"

```
"Physical AI" gets used loosely. Before comparing anything, it
helps to be explicit about what's being compared:

  - Perceives the physical world, acts only in software
    (e.g. an assistant that sees through a camera but completes
    tasks via search, email, or app control)

  - Predicts or simulates the physical world, but doesn't act
    (world models — used for planning or generating training data)

  - Directly drives physical actuators
    (robot manipulation, humanoid whole-body control, autonomous
    driving, drones — where output is a joint angle, a torque, a
    steering command)

We mostly focus on the third category, and try to be explicit
about which one we mean whenever it matters — mixing them into one
ranking is, in our opinion, one of the more common ways this space
misleads people.
```

## 4. 技术实现建议（给 Claude Code，不是硬性要求）

- **优先选最简单的技术方案**：一个 `index.html` + 一个 `style.css`，不需要引入 React/Vue 这类框架，也不需要构建步骤。这个页面的价值在文字和结构，不在交互复杂度。
- 如果 Ziqi 之后想更方便地加"Notes"条目或者维护"Landscape"列表，可以考虑一个轻量的静态站点生成方案（比如内容写在几个 Markdown/JSON 文件里，用一个很小的脚本生成 HTML），但**先做纯 HTML/CSS 的版本，跑起来看效果，不要一开始就上构建工具**。
- 锚点导航用原生 `<a href="#section-id">` 就够，平滑滚动可以加一行 CSS（`scroll-behavior: smooth`），不需要 JS 库。
- 表格（3.5 节）用原生 `<table>`，配合简单的 CSS 让它在窄屏上能横向滚动（`overflow-x: auto` 包一层），不需要额外的表格组件库。
- 网站名字、社交链接、邮箱这些容易变的信息，集中放在一处（比如 HTML 顶部的几个变量，或者一个小的 config），方便以后一次性改。
- 不需要做 CMS、不需要做后端、不需要做用户系统——纯静态站点即可，能直接部署到 GitHub Pages / Vercel / Netlify 这类平台。
