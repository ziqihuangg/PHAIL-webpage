```
Industrial / commercial tasks — bin-picking, sorting, assembly — PhAIL

  cross-company leaderboard we consider trustworthy yet (see About)
```

### 1.2 Metrics — 评测指标一览

表格，字段：**指标名 | 用在哪些基准 | 衡量什么 | 局限**

```
Binary success rate | Meta-World, RLBench, LIBERO, RoboTwin, ManiSkill3 |
  Did the task complete? | Coarse — hides near-misses, smoothness, safety

Chain / sequential success rate | CALVIN | Avg. # of consecutive subtasks
  completed (0-5) | Only for explicitly chained task designs

Partial-completion / progress score | RoboChallenge (Progress Score, 0-100,
  -0.5/retry), BEHAVIOR-1K (predicate-level Q-score), RoboDojo (avg score) |
  Credit for partial progress, not just pass/fail | Scoring rubric differs
  per benchmark, not comparable across them

Success-rate drop under perturbation | The Colosseum | Robustness across 14
  environment-perturbation axes | Measures robustness, not raw capability

Sim-real correlation (Pearson / MMRV) | SIMPLER | Whether sim ranking
  predicts real-robot ranking | Doesn't score capability directly

Pairwise preference / Elo | RoboArena | Head-to-head human preference across
  policies | Expensive, hard to scale, no absolute success number

Lifelong-learning transfer (FWT / NBT / AUC) | LIBERO | Forward transfer /
  negative backward transfer over a task sequence | Specific to
  continual-learning setups

Integration cost (engineering metric, not capability) | XPolicyLab | Time to
  plug a new policy into an eval harness | Infrastructure metric, not a
  model-quality metric

Throughput (units/hour) + MTBF | PhAIL | Industrial productivity and
  reliability | First real-world attempt at "economic" metrics — the metric
  we think the field is missing most (see About)

Not yet standardized anywhere we've found: cost per successful rollout
  (compute + robot-hour + material), longitudinal reliability drift over
  weeks of deployment, contamination / shortcut-solution auditing (see
  arXiv:2606.04233), safety/collision incidents, robustness to ambiguous
  instructions.
```

## 2. About 页面

把这段放进 `/about`，这是原来 v1 README 首页的内容，现在整体挪过来，基本不用改：

```
This is a research notebook, not a company.

Artificial Analysis has spent the last two years building an
independent, quantitative answer to "which AI model is actually
good?" — for language, image, video, and speech models. Physical
AI — models that perceive, predict, or act in the physical world,
from tabletop manipulation to full-body humanoid control to
autonomous driving — doesn't have an equivalent yet, and not by
accident: you can't call a robot the way you call an API.

This project is an attempt to build a small, honest piece of that
missing picture: a map of what's already being measured, by whom,
and how well; a growing, transparently-sourced comparison of the
models and benchmarks that matter; and, where something is clearly
missing, some proposals of our own.

Run out of [NTU / MMLab], updated irregularly, always a work in
progress. If you think something here is wrong, incomplete, or
missing, I'd genuinely like to hear about it — see Contact below.

---

What we mean by "physical AI"

"Physical AI" gets used loosely. Before comparing anything, it
helps to be explicit about what's being compared:

  - Perceives the physical world, acts only in software
    (e.g. an assistant that sees through a camera but completes
    tasks via search, email, or app control — Project Astra is the
    clearest current example)
  - Predicts or simulates the physical world, but doesn't act
    (world models — used for planning or generating training data)
  - Directly drives physical actuators
    (robot manipulation, humanoid whole-body control, autonomous
    driving, drones)

We mostly focus on the third category, and try to be explicit
about which one we mean whenever it matters — mixing them into one
ranking is, in our opinion, one of the more common ways this space
misleads people.

---

On scoring

Artificial Analysis can average different models into one
Intelligence Index because every model is run on the exact same
private test set. Most physical AI models are reported on
different task sets, different rollout counts, different labs —
the numbers are not comparable yet. Rather than force a fake
composite score, this site filters by task/embodiment/openness and
shows each reported number with its source. A real composite score
becomes honest once models are run through a shared harness (e.g.
SIMPLE, XPolicyLab) — that's a later milestone, not a v0 feature.

embodied/world models]
```

## 3. 设计规范（不变，重申一下）

- 单栏，白底黑字，藏青蓝 `#003366` 左右做链接色，无衬线系统字体栈。
- 顶部纯文字锚点导航，不要图标/汉堡菜单/sticky header。
- **表格用原生 `<table>`，窄屏加 `overflow-x: auto` 包一层横向滚动**，不要用卡片网格重新设计表格数据。
- 不加渐变、hero 大图、动画、图表组件库——1.2/1.3/1.4 这几张表本身就是"看板"，不需要额外做成可视化图表。
- 内容最大宽度 ~800-900px 居中（表格这里可以比纯文字段落略宽，因为列比较多，具体宽度 Claude Code 自行判断，不要为了凑窄栏宽度把表格挤得很难读）。
- 不要营销语言、不要 CTA 按钮、不要 pricing/testimonial/logo 墙。
